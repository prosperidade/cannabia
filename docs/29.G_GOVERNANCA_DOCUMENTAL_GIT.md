## 3. Pre-flight (obrigatório no início de TODA sessão Desktop)

Executar em ordem, abortando se qualquer passo falhar:

```bash
# 1. Estado limpo e atualizado
git status                      # working tree DEVE estar limpo; se não, ABORTAR e reportar
git checkout main
git fetch --all --prune
git pull origin main

# 2. Criar a branch do mergulho (nome exato do mapa da seção 2)
git checkout -b mergulho/29.X-<slug>

# 3. Verificações de contexto
# - Confirmar que os arquivos da lista LEIA ANTES DE COMEÇAR existem
# - Confirmar que docs/29.X_... ainda NÃO existe (se existir: ABORTAR — sessão duplicada)
# - Registrar no topo do relatório: data, hash do commit base (git rev-parse --short HEAD)
```

Se `git status` mostrar sujeira, ou a branch já existir local/remotamente, ou o relatório já existir: **abortar e reportar a Andre**. Pre-flight falho nunca se contorna.

---

## 4. Durante a sessão

- Commits pequenos e frequentes na branch do mergulho (proteção contra interrupção).
- Convenção de mensagem: `docs(29.X): <descrição curta>` — ex.: `docs(29.1): seção 1 — inventário de tabelas tenant_id/clinic_id`.
- Sessão interrompida: commitar o parcial com `docs(29.X): PARCIAL — <o que falta>` e push. A retomada continua na MESMA branch (exceção à regra de branch nova), após pre-flight reduzido (`git checkout` na branch + `git pull`).
- Proibido: `git push --force`, rebase de branch publicada, tocar em branch de outro mergulho, criar arquivos fora do mapa.

---

## 5. Encerramento da sessão (post-flight)

```bash
# 1. Relatório completo no formato padrão (6 seções) + evidências
git add docs/29.X_...
git commit -m "docs(29.X): relatório final do mergulho <hub>"
git push -u origin mergulho/29.X-<slug>

# 2. Abrir PR para main com o template da seção 6
# 3. NÃO mergear. Encerrar reportando a Andre: link do PR + resumo de 5 linhas
```

## 6. Template de PR

```
Título: [29.X] Mergulho <Hub> — relatório diagnóstico

## O que este PR contém
- docs/29.X_MERGULHO_<HUB>.md (novo)
- [29.5 apenas] docs/BACKLOG_SCC.md (completado)

## Checklist do executor
- [ ] Sessão foi 100% read-only sobre código/migrations/config
- [ ] Apenas arquivos do mapa de escrita foram criados/alterados
- [ ] Formato padrão de 6 seções respeitado
- [ ] Toda afirmação da seção 1 tem evidência (arquivo + trecho)
- [ ] Hash do commit base registrado no topo do relatório
- [ ] Linguagem: prontidão regulatória, nunca aprovação

## Top 3 achados (para triagem rápida do aprovador)
1. ...
2. ...
3. ...
```

**Política de merge (Andre):** squash merge (1 mergulho = 1 commit em `main`, histórico limpo e auditável). Merge apenas após leitura dos Top 3 + verificação do diff (só docs/).

---

## 7. Higiene pós-merge (main sempre livre)

Após cada merge, Andre (ou sessão autorizada) executa:

```bash
git checkout main && git pull origin main
git push origin --delete mergulho/29.X-<slug>   # limpa o remoto
git branch -d mergulho/29.X-<slug>              # limpa o local
git fetch --prune                               # remove referências mortas
git branch -a                                   # conferir: só main + branches de mergulhos ATIVOS
```

Estado-alvo permanente: `main` limpa e estável; nenhuma branch morta; branches vivas = mergulhos em execução, nada mais.

## 8. BLOCO DE GOVERNANÇA (colar no TOPO de todo prompt de handoff Desktop)

```
GOVERNANÇA (doc 29.G — obrigatória, prevalece sobre qualquer outra instrução):
1. Pre-flight: git status limpo -> checkout main -> fetch --prune -> pull ->
   criar branch mergulho/29.X-<slug>. Se qualquer passo falhar: ABORTAR e reportar.
2. Escrita autorizada SOMENTE em: <arquivos do mapa, seção 2 do 29.G>.
   Qualquer outro arquivo: PROIBIDO, mesmo que pareça útil.
3. Commits pequenos: docs(29.X): <descrição>. Push na branch do mergulho.
4. Ao final: PR para main com o template do 29.G. NÃO mergear — merge é
   prerrogativa exclusiva de Andre.
5. Nunca: push --force, commit em main, rebase de branch publicada, tocar
   em branch de outro mergulho.
6. Interrupção: commit PARCIAL + push; retomada na mesma branch.
7. Registrar no topo do relatório: data + hash do commit base.
```
